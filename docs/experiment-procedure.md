# Процедура экспериментов

Для каждой конфигурации сервинга будем использовать следующую постановку эксперимента. Под конфигурацией сервинга понимается модель + чекпоинт драфтинга. Всего есть такие конфигурации
- Дефолтная модель
- модель + дефолтный драфтер
- модель + драфтер, продолжили обучение на общих данных
- модель + драфтер, продолжили обучение на русских данных
- модель + драфтер, продолжили обучение на миксе данных


### Данные

- Русские запросы из WildChat
- Английские запросы из WildChat


К этим запросам добавляем системные промпты из `data/system_prompts`, задающие целевую длину ответа около 100, 500 или 1000 токенов. Полный вход, включая системный промпт, всю историю и chat template Qwen3, должен занимать 70–130 токенов. Thinking отключён (`enable_thinking=false`). Получаем такие профили:

- Префилл: ≈ 100 токенов
- Декод: ≈ 100, 500, 1000 токенов

Подготовка запросов из корня проекта:

```bash
.venv/bin/python scripts/prepare_wildchat_prompts.py
```

Скрипт читает первый Parquet-файл публичного [allenai/WildChat-1M](https://huggingface.co/datasets/allenai/WildChat-1M), около 231 MB. Файл сохраняется в кэш Hugging Face; весь датасет не скачивается. Версия датасета зафиксирована в скрипте. Прокси отключается только для процесса скрипта. Для чтения Parquet используется `pyarrow`, уже установленный в `.venv`; при необходимости установить: `uv pip install --python .venv/bin/python pyarrow`.

Отбираются первые 100 уникальных подходящих историй на каждом языке. История сохраняется до последнего сообщения пользователя включительно; последующий ответ из датасета не входит в запрос. Язык проверяется по разметке диалога и последнего сообщения пользователя.

Один и тот же набор из 100 запросов на язык должен укладываться в 70–130 токенов со всеми тремя системными промптами. Результат — шесть файлов `data/prompts/{ru,en}_{100,500,1000}.jsonl`. Каждая строка содержит готовые `messages` с системной инструкцией, `prompt_tokens`, `target_tokens` и `id` исходного диалога (`conversation_hash`). Источник и параметры отбора записываются в `data/prompts/metadata.json`. Фильтрация проверяет длину входа; длина будущего ответа задаётся инструкцией и может отклоняться от цели.

### Инструмент замера

В качестве фреймворка для сервинга LLM будем использовать `vllm`, версия `0.30.0`. Для замеров скорости будем использовать `AIPerf`, версия `0.13.0`. Будем замерять при следующих нагрузках:
- `concurrency=1`. То есть в полете всегда только один запрос
- `RPS=1`
- `RPS=2`
- `RPS=4`
- `RPS=8`
- `RPS=16`

Держим разминку 30 секунд, а потом основные замеры 120 секунд.

### Логируемые метрики

По итогу прогона по конфигурации (нагрузка, профиль запросов – различный декод) будем логгировать следующие метрики:
- RPS, нагрузка
- TTFT
- TPOT
- Latency
- Acceptance Rate
- Acceptance Length
