# Qwen3-8B с DFlash

Завершённая серия из 36 прогонов от 13 октября 2026 года, 15:45–18:07 МСК. Измеряет задержки, скорость и принятие draft-токенов для сравнения с [baseline без драфтера](../baseline_20261013_092255/README.md).

Деплой: 1 × NVIDIA H100 80 GB, GPU 2; `Qwen/Qwen3-8B`, BF16; драфтер `z-lab/Qwen3-8B-DFlash-b16`, ревизия `9b41424b7109f9c5413454f481b09a82b85333f4`, 15 draft-токенов. vLLM 0.30.0, AIPerf 0.13.0. Thinking и prefix caching отключены, CUDA graphs включены. Генерация использует настройки модели: temperature 0.6, top_p 0.95, top_k 20.

В этом деплое отключён FlashInfer autotune: его тестовый прогон в установленном vLLM вызывает ошибку CUDA при обращении к позициям за пределами контекста драфтера. У baseline autotune был включён и сохранил 0 подобранных конфигураций. Это отличие конфигураций зафиксировано в [deployment.json](deployment.json).

Данные и нагрузки совпадают с baseline: по 100 историй WildChat на RU и EN, полный вход 70–130 токенов; целевые длины ответа около 100/500/1000 токенов задаются системной инструкцией. Для каждого профиля выполнены `concurrency=1` и пуассоновские RPS 1/2/4/8/16: разминка 30 секунд, подача основной нагрузки 120 секунд, ожидание оставшихся ответов до 30 секунд.

## Файлы

- [tables.md](tables.md) — три итоговые таблицы, по 12 строк. Перцентили: p50 / p95 / p99. Acceptance Rate — доля принятых draft-токенов; Acceptance Length включает бонусный токен целевой модели. Используются отношения суммарных счётчиков.
- [runs/](runs/) — 36 исходных сводных JSON-отчётов AIPerf.
- [request_counts.csv](request_counts.csv) — отправленные, завершённые, отменённые запросы и ошибки основной фазы, извлечённые из лога AIPerf.
- [deployment.json](deployment.json) — сохранённая конфигурация, версии библиотек, ревизия драфтера и хеши входных файлов и скриптов.
- [serve_dflash.sh](serve_dflash.sh) — точная копия использованного скрипта запуска.

## Повторение

Хеши скриптов из конфигурации совпадают с кодом в коммите `3bd7f18d184cdad8101fff41fdf53125a0fe085f`. Поле `git_commit` в сохранённой конфигурации отражает HEAD до коммита изменений запуска DFlash.

Для повторения нужны локальная целевая модель `models/Qwen3-8B`, подготовленные файлы `data/prompts` и окружение `.venv` с зависимостями из `requirements.txt`; подготовка описана в [процедуре экспериментов](../../docs/experiment-procedure.md). Из корня проекта скачать зафиксированную ревизию драфтера и запустить сервер, затем во втором терминале — сетку:

```bash
.venv/bin/hf download z-lab/Qwen3-8B-DFlash-b16 --revision 9b41424b7109f9c5413454f481b09a82b85333f4 --local-dir models/Qwen3-8B-DFlash-b16
CUDA_VISIBLE_DEVICES=2 bash scripts/serve_dflash.sh
.venv/bin/python scripts/run_benchmarks.py --output-dir results/dflash_repeat
```

Каталог `results/dflash_repeat` должен быть новым. После серии он содержит `tables.md` и отдельные каталоги с исходными отчётами. Архив сохраняет файлы из `results/dflash_20261013_122940`; модели, кэши и подробные записи запросов остаются в исходной рабочей директории.
